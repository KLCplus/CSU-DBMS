# SQL 模块文件结构规划

本文档描述 `src/observer/sql` 目录的组织结构与职责划分，用于指导 SQL 引擎相关功能的开发、维护与定位。

SQL 模块是一个典型的 **流水线式 SQL 引擎**：词法/语法分析 → 语义解析（名字/表达式绑定）→ 逻辑计划 → 规则优化 → 物理计划 → 执行。整条链路在 `miniob` 框架的 SQL Stage 中编排。

---

## 1. 总览

```
src/observer/sql
├── parser/       词法分析、语法分析、语义解析（名字绑定）
├── stmt/         语句对象（AST 的面向对象表示）与语句工厂
├── expr/         表达式体系、元组（Tuple）、聚合器
├── operator/     逻辑算子 与 物理算子（执行算子）
├── optimizer/    逻辑/物理计划生成、重写与优化规则、Cascades 框架、统计信息
├── executor/     各类 SQL 语句执行器、结果集、执行阶段
├── plan_cache/   计划缓存
└── query_cache/  查询缓存
```

数据自左向右流转：

```
SQL 文本
  → parser/parse_stage    （词法 lex_sql.l + 语法 yacc_sql.y → parse_defs AST）
  → parser/resolve_stage  （语义解析：expression_binder 做名字/表达式绑定 → stmt/*）
  → optimizer/optimize_stage
       ├─ logical_plan_generator（stmt → operator/*_logical_operator）
       ├─ rewriter/各 rewrite rule（谓词下推、常量折叠、投影裁剪等）
       └─ physical_plan_generator（逻辑算子 → operator/*_physical_operator）
  → executor/execute_stage （语句执行器 + 物理算子执行 → sql_result 结果集）
```

## 2. 目录与文件说明

### 2.1 parser — 词法 / 语法 / 语义解析

| 文件 | 职责 |
| --- | --- |
| `lex_sql.l` | Flex 词法规则源文件，识别关键字、标识符、常量、运算符、字符串转义、注释（`--`、`/* */`）等 |

## 3. SQL 执行流水线（Stage 编排）

SQL 请求按以下阶段顺序处理（每个阶段由对应的 `*_stage.cpp` 实现）：

1. **ParseStage（parser/parse_stage）**：调用 `lex_sql` + `yacc_sql`，产出 AST（`parse_defs.h` 中的中间节点）。
2. **ResolveStage（parser/resolve_stage）**：调用 `ExpressionBinder` 做名字绑定与语义检查，产出 `stmt/*` 语句对象。
3. **OptimizeStage（optimizer/optimize_stage）**：
   - `LogicalPlanGenerator` 将 stmt 转为逻辑算子树；
   - `Rewriter` 应用各优化规则（谓词下推、常量折叠、投影裁剪等）；
   - `PhysicalPlanGenerator` 将逻辑算子树转为物理算子树。
4. **ExecuteStage（executor/execute_stage）**：由 `CommandExecutor` 分发到对应执行器/物理算子执行，结果写入 `SqlResult`。

可选阶段：`PlanCacheStage`（计划缓存）、`QueryCacheStage`（查询缓存）。
