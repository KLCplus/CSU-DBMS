# SQL 编译器文件结构规划（函数级）

本文档只描述**本人负责的 SQL 编译器层**：`src/observer/sql/parser/`（词法/语法/语义分析）与 `src/observer/sql/autocomplete/`（SQL 输入补全），并细化到**每个文件中的关键类与函数**。查询处理/执行与存储等层级不属于本人工作范围，本文档不再纳入。

- 路径约定：未写前缀的文件路径相对于 `src/observer/sql/`。
- 生成产物：`parser/lex_sql.cpp/.h` 与 `parser/yacc_sql.cpp/.hpp` 由 Flex/Bison 自动生成，不作为函数级说明对象；其源文件为 `parser/lex_sql.l` 与 `parser/yacc_sql.y`。

---

## 0. 范围与系统分层

本项目按「编译原理 × 数据库系统 × 操作系统」三层协作。**本文档只覆盖本人负责的 ① SQL 编译器层**；②③④ 为队友负责，仅在分层表中说明，不展开文件明细。

| 层 | 目录 | 职责 | 归属 |
| --- | --- | --- | --- |
| ① SQL 编译器层 | `sql/parser/`（`lex_sql.l`、`yacc_sql.y`、`parse.*`、`parse_stage`、`resolve_stage`、`expression_binder`）、`sql/autocomplete/` | 词法分析、语法分析、语义分析（名字绑定 / 类型检查），产出 AST 与语句对象；SQL 输入补全 | **本人** |
| ② 查询处理 / 执行层（数据库系统） | `sql/stmt/`、`sql/expr/`、`sql/optimizer/`、`sql/operator/`、`sql/executor/` | AST → 语句对象 → 逻辑计划 → 优化 → 物理计划 → 执行算子 | 队友 |
| ③ 存储引擎层（操作系统 / 存储） | `storage/` | 表 / 记录 / 页 / Buffer Pool / 索引 / 事务 / 日志 | 队友 |
| ④ 通信 / 服务 / 会话层 | `net/`、`service/`、`session/`、`event/` | 协议、鉴权、会话、结果下发 | 队友 |

边界说明：

- 本人负责的编译器层到**语义分析、产生 AST 与语句对象（`stmt/*`）为止**；`sql/stmt/` 是语义分析的产物、也是查询处理的输入，属于两层边界，项目分工上归**查询处理层（队友）**。
- 之后的一切（优化、算子、执行、存储读写）均属编译器**下游**，不在本文档与本人实现范围内。
- 项目基于 OceanBase Miniob 改造，`LICENSE` / `NOTICE` 保留上游版权说明。

## 1. 总览

编译器层是流水线的**前端**：词法分析 → 语法分析 → 语义解析（名字/表达式绑定）→ 产出 AST / 语句对象。

### 1.1 文件夹级结构

```
src/observer/sql
├── parser/       词法分析、语法分析、语义解析（名字绑定）
└── autocomplete/ SQL 输入补全（确定性 Parser+Catalog，可选 FIM 模型）
```

### 1.2 文件级结构树

> 未标后缀的单独条目即该文件名；`a.h / a.cpp` 表示一对同名头/源文件。

**parser/ —— 词法 / 语法 / 语义解析**

```
parser/
├── parse.h / parse.cpp                    语法解析总入口
├── parse_defs.h                           语法树中间节点、比较运算符与命令标志枚举
├── lex_sql.l                              词法规则源文件（交由 Flex 生成 lex_sql.cpp/.h）
├── yacc_sql.y                             语法与优先级源文件（交由 Bison 生成 yacc_sql.cpp/.hpp）
├── expected_tokens.h                      光标处期望 token 集合接口（补全与语法诊断复用）
├── expression_binder.h / expression_binder.cpp   表达式与名字绑定器（表/列存在性、类型校验）
├── parse_stage.h / parse_stage.cpp        语法解析阶段
└── resolve_stage.h / resolve_stage.cpp    语义解析阶段（名字绑定、语义错误透出）
```

**autocomplete/ —— SQL 输入补全**

```
autocomplete/
├── README.md                                      模块说明
├── completion_types.h / .cpp                      补全请求、响应与候选数据结构
├── current_statement_extractor.h / .cpp           取光标所在单条语句（分号/注释/字符串安全）
├── sql_text_scanner.h / .cpp                      轻量 SQL 文本扫描器（非语法分析器）
├── sql_capabilities.h / .cpp                      运行时 SQL 能力表（方言门禁）
├── grammar_completion_provider.h / .cpp           基于语法分析期望集合的关键字补全
├── catalog_completion_provider.h / .cpp           基于目录的表与列补全
├── completion_scope.h / .cpp                      补全作用域（来源/JOIN/插入目标）扫描
├── completion_engine.h / .cpp                     补全统一入口
├── sql_completion_config.h / .cpp                 补全配置加载
├── llama_completion_client.h / .cpp               模型填充接口客户端（带超时）
├── model_context_builder.h / .cpp                 模型上下文（受限方言与相关表结构）
├── model_completion_provider.h / .cpp             模型补全服务（健康检查、调用、降级）
└── model_completion_validator.h / .cpp            模型输出校验与最长合法前缀裁剪
```

### 1.3 编译数据流

```
SQL 文本
  → parser/lex_sql.l                          词法分析（token + 行列位置）
  → parser/yacc_sql.y                         语法分析 → parse_defs.h 的 AST
  → parser/resolve_stage + expression_binder  语义分析 / 名字绑定 → Stmt
（之后：逻辑计划 → 优化 → 物理计划 → 执行 → 存储，由队友负责，不在本文档范围）
```

## 2. 编译器 Stage 编排

| 阶段 | 实现（文件） | 关键函数 | 输入 → 输出 |
| --- | --- | --- | --- |
| ParseStage | `parser/parse_stage.*` | `ParseStage::handle_request` | SQL 字符串 → `ParsedSqlResult`（AST） |
| ResolveStage | `parser/resolve_stage.*` | `ResolveStage::handle_request` | AST → `Stmt *`（名字/表达式绑定） |

> `OptimizeStage`、`ExecuteStage` 属于下游（查询处理/执行层），由队友负责。

## 3. 编译器目录函数级明细

### 3.1 parser —— 词法 / 语法 / 语义解析

#### 3.1.1 解析入口与 AST 定义

| 文件 | 类/函数 | 说明 |
| --- | --- | --- |
| `parse.h` / `parse.cpp` | `parse()` | 语法解析总入口（`ParsedSqlResult::add_sql_node` 收集节点） |
| `parse_defs.h` | 各 AST 中间节点 | 见下方 |

`parse_defs.h` 定义的节点与枚举：

- **结构体（AST 节点）**：`RelAttrSqlNode`（表.列）、`ConditionSqlNode`（比较条件）、`JoinSqlNode`（显式 JOIN）、`SelectSqlNode`、`InsertSqlNode`、`DeleteSqlNode`、`UpdateSqlNode`、`AttrInfoSqlNode`（含 `nullable`）、`CreateTableSqlNode`、`DropTableSqlNode`、`AnalyzeTableSqlNode`、`CreateIndexSqlNode`、`DropIndexSqlNode`、`DescTableSqlNode`、`LoadDataSqlNode`、`SetVariableSqlNode`、`ExplainSqlNode`、`ErrorSqlNode`（`error_msg/line/column`）、`CalcSqlNode`。
- **枚举**：`CompOp`（`EQUAL_TO/LESS_EQUAL/NOT_EQUAL/LESS_THAN/GREAT_EQUAL/GREAT_THAN/IS_NULL/IS_NOT_NULL/NO_OP`）、`SqlCommandFlag`（`SCF_*`）。
- **类**：
  - `ParsedSqlNode`：`ParsedSqlNode()`（默认构造）、`ParsedSqlNode(SqlCommandFlag)`；承载 `flag` 与各语句节点联合体。
  - `ParsedSqlResult`：`add_sql_node()`（追加解析结果）、`sql_nodes()`（访问器）。

#### 3.1.2 词法/语法生成源

| 文件 | 关键点 |
| --- | --- |
| `lex_sql.l` | Flex 源：关键字/标识符/常量/运算符规则（含 `OR`）、`%x COMMENT` 多行注释状态、字符串转义（`''`/`""`/`\x`）、`%option yylineno` + `YY_USER_INIT`/`YY_USER_ACTION` 输出 **1-based 跨行行列**、`scan_string()` 绑定输入。生成 `lex_sql.cpp/.h`（`yylex` 等）。 |
| `yacc_sql.y` | Bison 源：文法与优先级（`%left/%precedence`，`OR < AND < 比较 < NOT`）、`%define parse.error custom` + `yyreport_syntax_error()`（位置 + unexpected + expected）、`unescape_quoted_string()`、`create_arithmetic_expression()`、`create_aggregate_expression()`、`set_expr_name_and_location()`、`append_join_node()`、`collect_expected_tokens()`（补全复用期望集合）。生成 `yacc_sql.cpp/.hpp`（`yyparse`）。 |
| `expected_tokens.h` | `collect_expected_tokens()` 声明：在 SQL 前缀末尾追加哨兵，复用 bison 期望集合，供自动补全使用。 |

#### 3.1.3 语义解析（名字/表达式绑定）

| 文件 | 类 | 关键函数 |
| --- | --- | --- |
| `expression_binder.h` / `expression_binder.cpp` | `ExpressionBinder`、`BinderContext` | `bind_expression`（分发入口）、`bind_star_expression`（`*` 展开）、`bind_unbound_field_expression`（字段→`FieldExpr` + 表/列存在性校验）、`bind_field_expression`、`bind_value_expression`、`bind_cast_expression`（类型转换）、`bind_comparison_expression`（含 `IS [NOT] NULL`）、`bind_conjunction_expression`（AND/OR）、`bind_arithmetic_expression`（算术 + 类型检查）、`bind_aggregate_expression`（聚合绑定）；`BinderContext::add_table`、`reset_binder_error_message`/`set_binder_error_message` |

#### 3.1.4 Stage

| 文件 | 类 | 关键函数 |
| --- | --- | --- |
| `parse_stage.h` / `.cpp` | `ParseStage` | `handle_request` |
| `resolve_stage.h` / `.cpp` | `ResolveStage` | `handle_request` |
