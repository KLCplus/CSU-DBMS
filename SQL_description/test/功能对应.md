# 功能对应说明（requirements.md 逐条 → 数据流 / 文件函数 / 实现原理）

本文按 `SQL_description/requirements.md` 的条目逐条对照实现，每个条目给出三点：
1. **数据流**：这条功能从 SQL 文本到结果的流转路径；
2. **功能函数位置**：承载该功能的文件（相对 `src/observer/`）与关键函数；
3. **实现原理**：核心思路与关键设计。

> 路径约定：`sql/` 相对 `src/observer/sql/`，`storage/`、`common/` 相对 `src/observer/`。

---

# 一、必须要完成的验收能力

## CREATE
- **数据流**：SQL 文本 → `ParseStage` 解析出 `CreateTableSqlNode` → `ResolveStage` 走 `Stmt::create_stmt` → `CreateTableStmt::create` → `OptimizeStage` 生成逻辑/物理计划 → `ExecuteStage` 执行 `CreateTableExecutor` → `Db::create_table` → 写 `TableMeta` 与数据文件、注册元数据。
- **功能函数位置**：`sql/stmt/create_table_stmt.cpp::CreateTableStmt::create`；`sql/executor/create_table_executor.cpp::CreateTableExecutor::execute`；`storage/db/db.cpp::Db::create_table`；`storage/table/table.cpp::Table::create`；`storage/table/table_meta.cpp::TableMeta::init`。
- **实现原理**：把列定义（类型/长度/可空/主键/存储格式）固化成 `TableMeta`，持久化表元数据文件并注册到目录（Catalog），建好数据文件与（可选）索引元数据；解析与绑定阶段完成类型/主键合法性校验。

## INSERT
- **数据流**：`InsertSqlNode` → `InsertStmt::create`（列清单映射 + 逐列类型校验）→ 逻辑计划 `InsertLogicalOperator` → 物理 `InsertPhysicalOperator::open` → `Table::make_record` 构造记录 → `Table::insert_record` 写入存储。
- **功能函数位置**：`sql/stmt/insert_stmt.cpp::InsertStmt::create`；`sql/optimizer/logical_plan_generator.cpp::create_plan(InsertStmt*)`；`sql/operator/insert_physical_operator.cpp::InsertPhysicalOperator::open`；`storage/table/table.cpp::Table::make_record` / `::insert_record` / `::set_value_to_record`。
- **实现原理**：支持 `INSERT INTO t VALUES(...)` 与 `INSERT INTO t(col1,col2) VALUES(...)`。列清单映射到表字段顺序，未列出列填 `NULL`；逐列做类型匹配（数值互转允许、`CHARS/INTS` 写 `DATES` 由存储层转换），不匹配时给出结构化 `TypeMismatch`；`make_record` 负责非空约束（`NOT NULL`）与空值位图。

## SELECT
- **数据流**：`SelectSqlNode` → `SelectStmt::create`（绑定表/列、构造 WHERE 表达式）→ `logical_plan_generator::create_plan(SelectStmt*)`（`TableGet`→`Predicate`→`GroupBy`→`Sort`→`Project`）→ 物理计划 → 执行时自底向上拉取元组 → 输出结果集。
- **功能函数位置**：`sql/stmt/select_stmt.cpp::SelectStmt::create`；`sql/optimizer/logical_plan_generator.cpp::create_plan(SelectStmt*)`；`sql/optimizer/physical_plan_generator.cpp::create_plan(...)`；`sql/operator/table_scan_physical_operator.cpp`、`sql/operator/project_physical_operator.cpp`。
- **实现原理**：`FROM` 决定数据源、`WHERE` 生成过滤、`SELECT 列表` 生成投影；执行采用火山模型（`open/next/close`），顶层 `Project` 逐行向子算子拉取，最终由 `SqlResult`/通信层输出。

## DELETE
- **数据流**：`DeleteSqlNode` → `DeleteStmt::create`（构造过滤条件）→ 逻辑计划 `DeleteLogicalOperator`（子节点 `TableGet` + `Predicate`）→ `DeletePhysicalOperator::next` 逐行删除 → 存储层删除记录。
- **功能函数位置**：`sql/stmt/delete_stmt.cpp::DeleteStmt::create`；`sql/optimizer/logical_plan_generator.cpp::create_plan(DeleteStmt*)`；`sql/operator/delete_physical_operator.cpp::DeletePhysicalOperator::next`。
- **实现原理**：把 `WHERE` 复用为过滤算子，扫描满足条件的记录并逐条 `delete_record`；`WHERE` 为空即全表删除。

## WHERE
- **数据流**：`WHERE` 子句 → 文法 `select_where: WHERE boolean_expr` 构造布尔表达式 → `ResolveStage` 经 `ExpressionBinder` 绑定为 `FieldExpr/ValueExpr/ComparisonExpr/ConjunctionExpr` → 逻辑计划 `PredicateLogicalOperator` → 物理 `PredicatePhysicalOperator`（或下推进 `TableScan` 的 `predicates`）。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`boolean_expr`）；`sql/parser/expression_binder.cpp::bind_comparison_expression` / `bind_conjunction_expression`；`sql/optimizer/logical_plan_generator.cpp`；`sql/operator/predicate_physical_operator.cpp::PredicatePhysicalOperator::next`；`sql/operator/table_scan_physical_operator.cpp::filter`。
- **实现原理**：用表达式树表达条件，执行时对每个元组求值得到布尔；谓词下推规则把可下推的比较条件下沉到扫描算子，减少向上传递的行数。

## 比较运算
- **数据流**：`age >= 18` → 文法 `expression comp_op expression` → `ComparisonExpr(comp, left, right)` → 执行时 `get_value` 取左右值 → `compare_value` 得到布尔。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`comp_op`）；`sql/expr/expression.cpp::ComparisonExpr::compare_value` / `::get_value`；`common/value.cpp::Value::compare`；类型比较实现 `common/type/{integer,float,char,date}_type.cpp`。
- **实现原理**：`=`/`==`、`!=`/`<>`、`<`、`<=`、`>`、`>=` 统一为 `CompOp`；比较按类型分发到具体 `DataType::compare`；`Value::compare` 特判 `NULL` 三值逻辑与布尔比较。

## AND
- **数据流**：`A AND B` → 文法 `boolean_expr AND boolean_expr` → `ConjunctionExpr(Type::AND, children)` → 执行 `get_value` 逐子表达式求值、遇 `false` 短路。
- **功能函数位置**：`sql/parser/yacc_sql.y`；`sql/expr/expression.cpp::ConjunctionExpr::get_value`。
- **实现原理**：合取表达式维护子表达式列表，`AND` 逻辑为“全真才真”，任一为假立即返回假（短路求值）。

## OR
- **数据流**：`A OR B` → 文法 `boolean_expr OR boolean_expr`（词法器补 `OR` 关键字）→ `ConjunctionExpr(Type::OR, children)` → 执行 `get_value` 逐子表达式求值、遇 `true` 短路。
- **功能函数位置**：`sql/parser/lex_sql.l`（`OR` 规则）；`sql/parser/yacc_sql.y`；`sql/expr/expression.cpp::ConjunctionExpr::get_value`。
- **实现原理**：与 `AND` 同一套合取表达式，`OR` 逻辑为“有一个真即真”；`PredicatePushdownRewriter` 对 `OR` 不再报错（不强行下推，保留在 `Predicate` 执行）。

## NOT
- **数据流**：`NOT x` → 文法 `NOT boolean_expr` → 构造 `x == false` 的 `ComparisonExpr` → 执行时先求 `x` 的布尔值再与 `false` 比较。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`NOT boolean_expr`）；`sql/expr/expression.cpp::ComparisonExpr`；`common/value.cpp::Value::compare`（布尔比较特判）。
- **实现原理**：把 `NOT` 降级为“等于 false”的比较；`Value::compare` 对 `BOOLEANS` 直接比较真假，保证 `NOT` 结果正确（修复了此前布尔走未实现比较恒为 false 的问题）。

## 括号
- **数据流**：`( boolean_expr )` → 文法 `LBRACE boolean_expr RBRACE` → 透传内部表达式 → 结合结构由括号决定。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`LBRACE boolean_expr RBRACE`）。
- **实现原理**：括号规则不改变语义、只改变结合顺序；配合优先级声明实现 `(a=1 or b=1) and c=1` 这类显式分组。

# 二、进阶版本

## UPDATE
- **数据流**：`UpdateSqlNode` → `UpdateStmt::create`（定位字段与条件）→ 逻辑计划 `UpdateLogicalOperator`（`TableGet` + `Predicate`）→ `UpdatePhysicalOperator::open` 逐行改写字段 → 事务层更新记录。
- **功能函数位置**：`sql/stmt/update_stmt.cpp::UpdateStmt::create`；`sql/optimizer/logical_plan_generator.cpp::create_plan(UpdateStmt*)`；`sql/operator/update_physical_operator.cpp::UpdatePhysicalOperator::open`。
- **实现原理**：先收集匹配记录（复制数据，避免扫描期间改页），再逐条写入新值；写值时**同步维护空值位图**，使“原值为 NULL 的字段”也能更新为具体值。

## ORDER BY
- **数据流**：`ORDER BY` 列表 → 文法 `order_by` → `SelectStmt` 记录 `order_by_units` → 逻辑计划 `SortLogicalOperator` → `SortPhysicalOperator` 收集全部行后按 key 排序输出。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`order_by`）；`sql/stmt/select_stmt.cpp`；`sql/optimizer/logical_plan_generator.cpp`；`sql/operator/sort_physical_operator.cpp::SortPhysicalOperator::evaluate_order_by` / `::next`。
- **实现原理**：排序算子缓存子算子全部元组，按 `OrderByUnit` 的表达式求值得到 key，按升/降序比较排序；`NULL` 参与比较时由三值逻辑处理。

## GROUP BY
- **数据流**：`GROUP BY` 与聚合表达式 → `SelectStmt` 记录 `group_by` 与聚合 → `logical_plan_generator::create_group_by_plan` → `GroupByLogicalOperator` → 物理 `HashGroupByPhysicalOperator`（有分组）或 `ScalarGroupByPhysicalOperator`（无分组标量聚合）。
- **功能函数位置**：`sql/parser/yacc_sql.y`；`sql/optimizer/logical_plan_generator.cpp::create_group_by_plan`；`sql/operator/hash_group_by_physical_operator.cpp::find_group`；`sql/operator/scalar_group_by_physical_operator.cpp`；`sql/expr/aggregator.cpp`。
- **实现原理**：哈希分组用分组键的 `ValueListTuple` 做哈希/比较确定组，逐行累加到聚合器（`SUM/COUNT/AVG/MIN/MAX`）；聚合器跳过 `NULL`，空组返回 `NULL`。

## JOIN
- **数据流**：显式 `JOIN ... ON` 或 `FROM a,b` → 文法 `join_clause` / `rel_list` → `SelectStmt` 记录 `joins` → 逻辑计划 `JoinLogicalOperator` → 物理 `NestedLoopJoinPhysicalOperator` 或 `HashJoinPhysicalOperator`。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`join_clause`）；`sql/stmt/select_stmt.cpp`；`sql/optimizer/logical_plan_generator.cpp::create_plan(SelectStmt*)`；`sql/operator/nested_loop_join_physical_operator.cpp::next`；`sql/operator/hash_join_physical_operator.cpp`；`sql/optimizer/physical_plan_generator.cpp::can_use_hash_join`。
- **实现原理**：多表时逐层构造 `Join` 节点，连接条件作为过滤表达式；等值连接在数据量较大/代价更低时选哈希连接，否则嵌套循环连接。

## 算术表达式
- **数据流**：`age + 1` → 文法 `expression '+' expression` → `ArithmeticExpr(ADD, left, right)` → 绑定阶段做类型检查 → 执行 `get_value` 调 `calc_value` → 委托 `Value::add/subtract/...`。
- **功能函数位置**：`sql/parser/yacc_sql.y`（算术规则与 `create_arithmetic_expression`）；`sql/expr/expression.cpp::ArithmeticExpr::calc_value` / `::get_value` / `::get_column`；`sql/expr/arithmetic_operator.hpp`。
- **实现原理**：`INT+INT→INT`、含浮点则 `FLOAT`；一元负号（`NEGATIVE`）支持空右操作数；类型不符（如 `INT+VARCHAR`）在绑定阶段直接报错，不进入执行。

## NULL
- **数据流**：`NULL` 字面量/可空列 → `Value::set_null`（`is_null_` 标志）→ 比较 `ComparisonExpr::compare_value` 三值逻辑 → `IS [NOT] NULL` 特判 → 存储层空值位图 → 读取 `RowTuple::cell_at` 按位图返回 NULL。
- **功能函数位置**：`common/value.h` / `common/value.cpp::Value::set_null/is_null/compare`；`sql/expr/expression.cpp::ComparisonExpr::compare_value`；`sql/expr/tuple.h::RowTuple::cell_at`；`storage/table/table.cpp::Table::make_record` / `::set_value_to_record`；`storage/table/table_meta.cpp`（空值位图偏移/大小）。
- **实现原理**：`NULL` 与类型解耦，用独立标志表示；比较时任一操作数为空返回未知（WHERE 按 false 处理）；存储用位图标记空字段；聚合跳过 `NULL`。

# 三、词法分析器

## 1. SQL 文件
- **数据流**：读入整个 SQL 文件内容作为字符串 → `ParseStage` 调 `parse()` → `scan_string` 绑定缓冲 → `yylex`/`yyparse` 逐条解析 → 过滤掉注释/空白后按分号切出多条语句。
- **功能函数位置**：`sql/parser/parse.cpp::parse`；`sql/parser/parse_stage.cpp::ParseStage::handle_request`；`sql/parser/lex_sql.l::scan_string`。
- **实现原理**：文件内容一次性送入词法/语法分析；注释与空白在词法层忽略，语句边界由分号决定，天然支持“一个文件多条语句”。

## 2. 单条 SQL 语句
- **数据流**：单条 SQL → 解析为一个 `ParsedSqlNode` → 走完整流水线（Resolve→Optimize→Execute）。
- **功能函数位置**：`sql/parser/yacc_sql.y::sql_parse`；`sql/parser/parse_stage.cpp`；`sql/executor/execute_stage.cpp`。
- **实现原理**：单条语句是最小处理单元；以 `;` 或 `\g` 结束，解析结果为节点列表中的第一个。

## 3. 多条 SQL 语句
- **数据流**：多条 SQL → 文法 `commands: commands command_wrapper opt_semicolon` 逐个累加为节点列表 → `ParseStage` 检查任一条是否解析出错 → 无错误则取用。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`commands` 规则）；`sql/parser/parse_stage.cpp::ParseStage::handle_request`。
- **实现原理**：`commands` 递归累积每个 `command_wrapper`；只要任一节点是 `SCF_ERROR` 即整体反馈错误，避免“尾部非法内容被静默忽略”。

## 输出 `<TokenType, Lexeme, Line, Column>`
- **数据流**：扫描每个 token → `YY_USER_ACTION` 写 `yylloc`（`first_line/last_line/first_column/last_column`）→ 文法规约时把行列写进表达式/错误节点。
- **功能函数位置**：`sql/parser/lex_sql.l`（`%option yylineno`、`YY_USER_INIT`、`YY_USER_ACTION`）。
- **实现原理**：启用 `yylineno` 跟踪行号，列号从 1 开始、遇换行重置；token 文本即 `yytext`，类型为 `yylex` 返回值。

## 1. 识别关键字
- **数据流**：`select` → 关键字规则（大小写不敏感）→ 返回对应 token（如 `SELECT`）→ 文法规约。
- **功能函数位置**：`sql/parser/lex_sql.l`（关键字规则段，如 `SELECT RETURN_TOKEN(SELECT)`）。
- **实现原理**：为每个已实现关键字写独立规则并返回具名 token；未实现的关键字不登记，从而不会“凭空”支持方言。

## 2. 识别标识符
- **数据流**：`student` → `{ID}` 规则 → `yylval->cstring` 携带原文 → 文法作为表名/列名。
- **功能函数位置**：`sql/parser/lex_sql.l`（`ID [A-Za-z_]+[A-Za-z0-9_]*`）。
- **实现原理**：标识符原文以 `strdup` 保存并由 scanner 统一释放；表/列匹配阶段大小写不敏感。

## 3. 识别常量
- **数据流**：`18` / `1.5` / `'Tom'` → `NUMBER` / `FLOAT` / `SSS` → 文法构造 `Value`。
- **功能函数位置**：`sql/parser/lex_sql.l`（`{DIGIT}+`、`{DIGIT}+\.{DIGIT}+`、字符串规则）；`sql/parser/yacc_sql.y`（`value`）。
- **实现原理**：整数/浮点分别转 `int/float`；字符串去引号并转义后建 `Value`。

## 4. 识别运算符
- **数据流**：`>= <= != <> == = < > + - * /` → 运算符规则 → 具名 token 或返回字符 → 文法比较/算术规则。
- **功能函数位置**：`sql/parser/lex_sql.l`（运算符规则段）。
- **实现原理**：多字符运算符优先匹配（`>=` 先于 `>`）；`==`/`=`→`EQ`，`!=`/`<>`→`NE`；`+ - * /` 返回字符，文法用 `%left` 声明结合性。

## 5. 识别分隔符
- **数据流**：`( ) , ; .` → 分隔符规则 → `LBRACE/RBRACE/COMMA/SEMICOLON/DOT`。
- **功能函数位置**：`sql/parser/lex_sql.l`。
- **实现原理**：分隔符作为独立 token，支撑表达式括号、列清单、语句结束与 `表.列` 限定名。

## 6. 跳过空白
- **数据流**：空格/制表/换行 → 空白规则 → 不产生 token。
- **功能函数位置**：`sql/parser/lex_sql.l`（`WHITE_SPACE`、`\n`）。
- **实现原理**：空白匹配后直接忽略；换行同步重置列号并让 `yylineno` 自增。

## 7. 跳过注释
- **数据流**：`-- ...` 到行尾、`/* ... */` 跨行 → 注释规则 → 不产生 token。
- **功能函数位置**：`sql/parser/lex_sql.l`（`"--"[^\n]*`、`"/*"` + `%x COMMENT` 状态）。
- **实现原理**：单行注释匹配到换行；块注释用独立状态 `<COMMENT>` 吞掉内容直到 `*/` 恢复。

## 8. 处理字符串
- **数据流**：`'Alice'` / `"dq"` → 字符串规则 → `SSS` 携带带引号原文 → `value` 去引号建 `Value`。
- **功能函数位置**：`sql/parser/lex_sql.l`（单/双引号规则）。
- **实现原理**：正则允许内部转义序列，保证 `'Tom''s book'` 整体作为一个字符串 token。

## 9. 处理转义
- **数据流**：`'Tom''s'` / `'a\\b'` → `SSS` → `yacc_sql.y::unescape_quoted_string` → 还原为 `Tom's` / `a\b`。
- **功能函数位置**：`sql/parser/yacc_sql.y::unescape_quoted_string`；`sql/parser/lex_sql.l`（字符串正则含 `\\.`、`''`、`""`）。
- **实现原理**：连续同引号 `''`/`""` 表示一个引号，反斜杠转义 `\x` 表示 `x`；在解析阶段统一还原再建 `Value`。

## 10. 大小写不敏感（统一处理）
- **数据流**：`SeLeCt` → 关键字规则大小写不敏感匹配；`AgE`/`P` → 绑定时大小写不敏感查找表/列。
- **功能函数位置**：`sql/parser/lex_sql.l`（`%option case-insensitive`）；`storage/db/db.cpp::Db::find_table`；`storage/table/table_meta.cpp::TableMeta::field`。
- **实现原理**：词法层折叠关键字大小写；标识符层表名/列名查找用 `strcasecmp`，实现“关键字与标识符统一大小写不敏感”。

## 测试要求：非法输入返回“错误类型 + 位置 + 原因”，且不崩溃
- **数据流**：非法字符/未闭合字符串 → 词法返回字符或字符串缺失 → 语法错误 → `yyreport_syntax_error` 生成 `SyntaxError` 消息（含位置/实际符号/期望集合）→ `ParseStage` 透出。
- **功能函数位置**：`sql/parser/lex_sql.l`（兜底 `.` 规则）；`sql/parser/yacc_sql.y::yyreport_syntax_error`；`sql/parser/parse_stage.cpp`。
- **实现原理**：无法识别的字符不在语法符号表中，bison 在该处报错；补全/诊断通过 `yypcontext_*` 给出位置与实际/期望符号，异常不越界、不崩溃。

### 测试点：注释型输入
- **数据流**：`-- single line` / `/* multi-line */` → 注释规则 → 忽略。
- **功能函数位置**：`sql/parser/lex_sql.l`。
- **实现原理**：块注释用状态机，单行注释到行尾。

### 测试点：多字符运算符
- **数据流**：`>= <= != ==` → 多字符规则优先。
- **功能函数位置**：`sql/parser/lex_sql.l`。
- **实现原理**：长匹配优先，避免被拆成两个单字符 token。

### 测试点：字符串
- **数据流**：`'Alice' Tom''s book'` → 字符串规则 + 转义还原。
- **功能函数位置**：`sql/parser/lex_sql.l`；`sql/parser/yacc_sql.y::unescape_quoted_string`。
- **实现原理**：连续引号视作转义，保证分词连续。

### 测试点：大小写
- **数据流**：`select SELECT SeLeCt` → 大小写不敏感关键字。
- **功能函数位置**：`sql/parser/lex_sql.l`。
- **实现原理**：`%option case-insensitive`。

### 测试点：非法输入
- **数据流**：`@` / 未闭合字符串 / 非法数字 → 词法/语法错误 → 结构化报错。
- **功能函数位置**：`sql/parser/lex_sql.l`；`sql/parser/yacc_sql.y::yyreport_syntax_error`。

### 测试点：整段用例测试
- **数据流**：注释 + 多行 SELECT/WHERE/AND/多字符运算符/字符串 → 完整解析并执行。

# 四、语法分析

## 输入（Token Stream）/ 输出（AST）
- **数据流**：`yylex` 产出的 token 流 → `yyparse` 按 LALR(1) 表规约 → 构造 `parse_defs.h` 的 AST 节点 → `ParsedSqlResult`。
- **功能函数位置**：`sql/parser/yacc_sql.y`（规约动作）；`sql/parser/parse_defs.h`；`sql/parser/parse.cpp::parse`。
- **实现原理**：规约动作里直接 new 出 `SelectSqlNode/InsertSqlNode/...`，把 token 文本、`Value`、子表达式组装成 AST。

## 1. 理解优先级 NOT > 比较 > AND > OR
- **数据流**：`a=1 or b=1 and c=1` → 文法按优先级规约 → 生成 `a=1 OR (b=1 AND c=1)` 的表达式树。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`%left OR`、`%left AND`、`%left LT GT LE GE EQ NE`、`%precedence NOT`，见 `boolean_expr`）。
- **实现原理**：bison 中后声明的优先级更高；按“OR < AND < 比较 < NOT”排列，冲突时 shift/reduce 结果符合语义。

## 2. 括号可显式改变结合结构
- **数据流**：`( ... )` → `LBRACE boolean_expr RBRACE` → 内部子表达式作为整体参与外层。
- **功能函数位置**：`sql/parser/yacc_sql.y`。
- **实现原理**：括号规则返回内部表达式，从而覆盖默认优先级实现显式分组。

## 3. 消除左递归
- **数据流**：表达式/布尔式规则以左递归形式书写（`expression '+' expression`、`boolean_expr AND boolean_expr`）。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`expression`、`boolean_expr`）。
- **实现原理**：采用自底向上的 LALR(1)（bison）天然支持左递归，无需手写消除；优先级声明解决表达式的结合方向。

## 4. 构造 FIRST 集
- **数据流**：文法分析阶段计算各非终结符的 FIRST 集，用于构造分析表。
- **功能函数位置**：由 bison 在生成 `yacc_sql.cpp` 时计算（见生成的 LALR 表与 `yytname`）。
- **实现原理**：FIRST 集表示“某非终结符可能以哪些终结符开头”，是构造分析表的基础；工程上用工具自动完成。

## 5. 构造 FOLLOW 集
- **数据流**：文法分析阶段计算 FOLLOW 集，决定规约时机。
- **功能函数位置**：由 bison 自动计算。
- **实现原理**：FOLLOW 集表示“某非终结符后面可能跟哪些终结符”，与 FIRST 一起决定 LALR 表项。

## 6. LL(1) 表
- **数据流**：把 FIRST/FOLLOW 信息组织成预测分析表，指导自顶向下解析。
- **功能函数位置**：概念对应 bison 生成的 LALR(1) 分析表；期望集合接口 `sql/parser/expected_tokens.h::collect_expected_tokens`。
- **实现原理**：LL(1) 用“栈 + 分析表”做预测分析；本项目采用更强大的 LALR(1)（自底向上），并复用其状态给出“当前位置允许的 token 集合”，等价地暴露了表信息。

## 7. 梯度下降（按编译原理应为“递归下降/预测分析”）
- **数据流**：对每个非终结符写一个递归过程，按当前 token 选择产生式。
- **功能函数位置**：概念对应 `yacc_sql.y` 的分层非终结符（`commands → command_wrapper → select_stmt → ...`）。
- **实现原理**：需求此处表述为“梯度下降”，按编译原理上下文应为“递归下降（预测分析）”；本项目的分层文法规则可映射为递归下降结构，但实现上使用表驱动的 LALR(1) 解析器完成同类工作。

## 8. LR（可选挑战）
- **数据流**：用 LR 分析表做自底向上移进-规约。
- **功能函数位置**：`sql/parser/yacc_sql.y`（bison 生成的 LALR(1) 表，位于 `yacc_sql.cpp`）。
- **实现原理**：本项目直接采用 **LALR(1)**（LR 家族），即已完成该“可选挑战”；`%left/%precedence` 用于消解移进-规约冲突。

## 9. 语法诊断：错误位置 + 实际符号 + 期望集合
- **数据流**：语法错误 → `yyreport_syntax_error` 用 `yypcontext_token` 取实际符号、`yypcontext_expected_tokens` 取期望集合 → 组织为 `SyntaxError` 文本 → `ParseStage` 透出。
- **功能函数位置**：`sql/parser/yacc_sql.y::yyreport_syntax_error`；`sql/parser/parse_stage.cpp`。
- **实现原理**：`%define parse.error custom` 让解析器把“位置/实际符号/期望集合”交给自定义回调；未识别字符回填原始字符，未闭合字符串给出专门原因。

# 五、语义分析

## 1. 验证表存在性
- **数据流**：`FROM student` → 解析得表名 → `SelectStmt::create` 调 `Db::find_table` → 不存在则报 `SCHEMA_TABLE_NOT_EXIST`。
- **功能函数位置**：`sql/stmt/select_stmt.cpp::SelectStmt::create`；`storage/db/db.cpp::Db::find_table`。
- **实现原理**：以表名查当前数据库的表集合；查找大小写不敏感，未命中即语义错误。

## 2. 验证列存在性
- **数据流**：`SELECT score` → `bind_unbound_field_expression` → `TableMeta::field("score")` → 为空则报 `SemanticError ... no such field`。
- **功能函数位置**：`sql/parser/expression_binder.cpp::bind_unbound_field_expression`；`storage/table/table_meta.cpp::TableMeta::field`。
- **实现原理**：在绑定阶段把 `UnboundFieldExpr` 解析为 `FieldExpr`，查不到列立即报错并记录位置。

## 3. 名字绑定
- **数据流**：未绑定表达式（`UnboundFieldExpr`/`StarExpr`/`UnboundAggregateExpr`）→ `ExpressionBinder::bind_expression` 按类型分发 → 产出已绑定的 `FieldExpr/AggregateExpr` 等。
- **功能函数位置**：`sql/parser/expression_binder.cpp::bind_expression` 及 `bind_star_expression`/`bind_unbound_field_expression`/`bind_aggregate_expression` 等；`BinderContext::add_table`/`find_table`。
- **实现原理**：绑定器持有当前查询的表集合，把“名字”解析为“字段对象”，并顺带完成存在性与类型检查。

## 4. 类型一致性
- **数据流**：`age + 'abc'` → `bind_arithmetic_expression` 取左右 `value_type()` → 非法组合 → 生成 `SemanticError: operator '+' cannot be applied to INT and VARCHAR`。
- **功能函数位置**：`sql/parser/expression_binder.cpp::bind_arithmetic_expression` / `set_arithmetic_type_error`；`common/type/attr_type.cpp::attr_type_to_sql_string`。
- **实现原理**：算术只接受数值类型（`INT/FLOAT`）；`INT/INT→INT`、含浮点→`FLOAT`；错误消息用面向用户的类型名并带行列位置。

## 5. INSERT 匹配
- **数据流**：`INSERT ... VALUES(...)` → `InsertStmt::create` 校验“值个数=列个数”并逐列比对类型 → 不匹配给出 `TypeMismatch`。
- **功能函数位置**：`sql/stmt/insert_stmt.cpp::InsertStmt::create`。
- **实现原理**：支持列清单映射与省略列填 `NULL`；数值类型互转允许，`CHARS/INTS→DATES` 放行由存储层转换；逐列聚合不匹配原因后一次性报告。

## 6. Catalog 提供 createTable / findTable / findColumn / getType
- **数据流**：建表经 `Db::create_table`；查表经 `Db::find_table`；查列/类型经 `TableMeta::field` + `FieldMeta::type`。
- **功能函数位置**：`storage/db/db.cpp::Db::create_table` / `::find_table`；`storage/table/table_meta.cpp::TableMeta::field`；`storage/field/field_meta.cpp::FieldMeta::type`；`catalog/catalog.h::Catalog`（统计）。
- **实现原理**：`Db` 维护已打开表集合，`TableMeta`/`FieldMeta` 提供列与类型元数据，等价满足 Catalog 的四类接口。

## 7. Catalog 服务执行引擎与持久化
- **数据流**：执行引擎经 `Db`/`TableMeta` 读元数据；建表/建索引时把元数据写入目录并持久化，重启时加载。
- **功能函数位置**：`storage/catalog/schema_catalog.*`；`storage/table/table_meta.cpp`（`serialize/deserialize`）；`storage/db/db.cpp::Db::open_all_tables`。
- **实现原理**：元数据序列化为 JSON 存于系统目录，启动时反序列化恢复表/索引信息，供执行引擎与补全使用。

## 8. 完成名字绑定
- **数据流**：同“名字绑定”——所有未绑定节点在 `ResolveStage` 内被解析为已绑定表达式。
- **功能函数位置**：`sql/parser/resolve_stage.cpp::ResolveStage::handle_request`；`sql/parser/expression_binder.cpp`。
- **实现原理**：每条语句的 `create` 内部调用绑定器；绑定完成才生成 `Stmt`，保证后续计划阶段的表达式都“有对象、有类型、有位置”。

## 9. 简化类型系统（集中管理）
- **数据流**：类型规则集中在 `AttrType`/`DataType` 与绑定器；解析器/执行器不散落类型判断。
- **功能函数位置**：`common/type/attr_type.{h,cpp}`、`common/type/data_type.{h,cpp}`、各 `*_type.cpp`；`sql/parser/expression_binder.cpp`（算术/比较类型规则）。
- **实现原理**：用枚举 + 类型实例统一表达类型与转换代价（`cast_cost`），把“可转换/必须报错”的判定集中在绑定阶段。

### INT + INT -> INT
- **数据流**：`a + b`（均为 INT）→ `ArithmeticExpr::value_type()` 判定 → 结果类型 INT → `calc_value` 走整数加法。
- **功能函数位置**：`sql/expr/expression.cpp::ArithmeticExpr::value_type` / `::calc_value`；`common/value.cpp::Value::add`。
- **实现原理**：左右都是整型且非除法时结果取 `INTS`，以整数运算模板执行。

### INT > INT -> BOOL
- **数据流**：`a > b` → `ComparisonExpr` 求左右值 → `compare_value` → 结果为布尔。
- **功能函数位置**：`sql/expr/expression.cpp::ComparisonExpr::value_type`（返回 `BOOLEANS`）/ `::compare_value`；`common/type/integer_type.cpp::compare`。
- **实现原理**：比较表达式静态类型恒为布尔，运行期按类型比较得出真假。

### VARCHAR = VARCHAR -> BOOL
- **数据流**：`name = 'Bob'` → 左右均 `CHARS` → 字符串比较 → 布尔结果。
- **功能函数位置**：`sql/expr/expression.cpp::ComparisonExpr::compare_value`；`common/type/char_type.cpp::compare`。
- **实现原理**：字符串按类型比较实现逐字符比较，相等返回真。

### BOOL AND BOOL -> BOOL
- **数据流**：`A AND B` → `ConjunctionExpr` 逐子式求布尔 → 短路 → 布尔结果。
- **功能函数位置**：`sql/expr/expression.cpp::ConjunctionExpr::value_type` / `::get_value`。
- **实现原理**：合取静态类型为布尔；`AND` 全真才真，遇假短路。

### NOT BOOL -> BOOL
- **数据流**：`NOT x` → 降级为 `x == false` → 布尔比较 → 布尔结果。
- **功能函数位置**：`sql/parser/yacc_sql.y`（`NOT boolean_expr`）；`sql/expr/expression.cpp::ComparisonExpr`；`common/value.cpp::Value::compare`（布尔特判）。
- **实现原理**：`NOT` 结果仍为布尔，`Value::compare` 对布尔直接比较真假。

### INT + VARCHAR -> ERROR
- **数据流**：`age + 'abc'` → `bind_arithmetic_expression` 检查左右类型 → 发现非数值 → 报语义错误并定位到运算符。
- **功能函数位置**：`sql/parser/expression_binder.cpp::bind_arithmetic_expression` / `set_arithmetic_type_error`；`common/type/attr_type.cpp::attr_type_to_sql_string`。
- **实现原理**：算术只允许数值类型；非法组合生成 `SemanticError: operator '+' cannot be applied to INT and VARCHAR`，不进入执行。

## 10. 语义错误报告“类型 + 位置 + 原因”
- **数据流**：语义错误 → 绑定器写入线程本地消息（含 `line/column` 与原因）→ `ResolveStage` 读消息并设为结果状态 → 客户端展示。
- **功能函数位置**：`sql/parser/expression_binder.cpp`（`set_binder_error_message`/`set_arithmetic_type_error`）；`sql/parser/resolve_stage.cpp`；`sql/stmt/insert_stmt.cpp`。
- **实现原理**：表达式携带行列（`set_location`），错误消息统一经线程本地槽位透出，避免污染正常流程。

### 例1：算术类型错误
- **数据流**：`WHERE age + 'abc' > 20` → 绑定算术表达式时发现 `INT + VARCHAR` → 生成 `SemanticError at line L, column C`（定位到 `+`）。
- **功能函数位置**：`sql/parser/expression_binder.cpp::set_arithmetic_type_error`；`sql/parser/yacc_sql.y::create_arithmetic_expression`（记录运算符位置）。
- **实现原理**：算术表达式的位置记录为运算符位置；类型非法即报错并携带行/列与原因（`operator '+' cannot be applied to INT and VARCHAR`）。

### 例2：INSERT 类型不匹配
- **数据流**：`INSERT INTO student(id,name) VALUES ('Alice', 1)` → `InsertStmt::create` 逐列比对 → 汇总为 `TypeMismatch`。
- **功能函数位置**：`sql/stmt/insert_stmt.cpp::InsertStmt::create`。
- **实现原理**：列清单按名映射到字段后逐列检查类型，把每列“期望类型 vs 实际类型”逐行输出：
  `student.id expects INT, but VARCHAR found.` / `student.name expects VARCHAR, but INT found.`

# 六、系统工程

## 编译器与数据库接口

### 1. CREATETABLE
- **数据流**：同 CREATE：`CreateTableStmt` → `CreateTableExecutor` → `Db::create_table` → 注册元数据。
- **功能函数位置**：`sql/stmt/create_table_stmt.cpp`；`sql/executor/create_table_executor.cpp`；`storage/db/db.cpp`。
- **实现原理**：创建表对象、元数据文件与数据文件，并注册到目录。

### 2. INSERT
- **数据流**：`InsertPhysicalOperator::open` → `Table::make_record` → `Table::insert_record`。
- **功能函数位置**：`sql/operator/insert_physical_operator.cpp`；`storage/table/table.cpp`。
- **实现原理**：构造定长记录并写入存储引擎（Heap/LSM）。

### 3. SeqScan
- **数据流**：`TableGet` → `TableScanPhysicalOperator::open/next` → 记录扫描器逐条读记录 → 包成 `RowTuple`。
- **功能函数位置**：`sql/operator/table_scan_physical_operator.cpp`；`storage/table/table.cpp::Table::get_record_scanner`。
- **实现原理**：顺序扫描全部记录；过滤器在扫描时就地判断，减少向上传递。

### 4. Filter
- **数据流**：`WHERE` → `PredicatePhysicalOperator`（或下推到扫描算子 `predicates`）→ 对每个元组求值布尔。
- **功能函数位置**：`sql/operator/predicate_physical_operator.cpp`；`sql/operator/table_scan_physical_operator.cpp::filter`。
- **实现原理**：表达式求值得到布尔，假则丢弃该行。

### 5. Project
- **数据流**：`ProjectPhysicalOperator::current_tuple` → `ExpressionTuple` 对子元组求值 → 输出指定列。
- **功能函数位置**：`sql/operator/project_physical_operator.cpp::ProjectPhysicalOperator`。
- **实现原理**：按 `SELECT` 的表达式列表求值并组装输出元组。

### 6. 输出 JSON
- **数据流**：执行结果 → `SqlResult` → 服务边界 `QueryResult` → `to_json` 序列化 → 通信层下发。
- **功能函数位置**：`sql/executor/sql_result.cpp`；`service/query_result.h`；`net/native_communicator.cpp::to_json`。
- **实现原理**：统一值类型结果对象（列/行/状态）序列化为 JSON，客户端按 JSON 渲染。

## AST 到 Logical Plan

### 1. FROM 决定数据源
- **数据流**：`FROM t` → `create_plan(SelectStmt*)` 为每个表建 `TableGetLogicalOperator`，多表时逐层包 `JoinLogicalOperator`。
- **功能函数位置**：`sql/optimizer/logical_plan_generator.cpp::create_plan(SelectStmt*)`。
- **实现原理**：`FROM` 列表是计划的叶子/连接输入；先建源算子再向上叠加其它算子。

### 2. WHERE 生成 Filter
- **数据流**：`WHERE expr` → 构造 `PredicateLogicalOperator(expr)` 并挂到源算子之上。
- **功能函数位置**：`sql/optimizer/logical_plan_generator.cpp`（`where_expression` 分支）。
- **实现原理**：过滤算子只持有条件表达式，执行期逐行求值。

### 3. SELECT 列表生成 Project
- **数据流**：`SELECT e1,e2` → 构造 `ProjectLogicalOperator(expressions)` 作为计划顶层。
- **功能函数位置**：`sql/optimizer/logical_plan_generator.cpp`。
- **实现原理**：投影算子保存输出表达式，最后做列裁剪/输出。

### 4. Plan 节点只保存执行所需信息
- **数据流**：各逻辑算子保存“表/表达式/排序键/分组键”等最小信息，不保存解析中间态。
- **功能函数位置**：`sql/operator/*_logical_operator.{h,cpp}`。
- **实现原理**：逻辑算子与 AST 解耦，只保留执行语义所需字段，便于重写与物理化。

## 规则式优化

### 1. 常量折叠
- **数据流**：`age > 10+8` → 重写规则把 `10+8` 求值为 `18` → `age > 18`。
- **功能函数位置**：`sql/optimizer/arithmetic_simplification_rule.cpp::ArithmeticSimplificationRule::rewrite`；`sql/optimizer/expression_rewriter.cpp`。
- **实现原理**：对常量子表达式调 `try_get_value` 提前求值，用 `ValueExpr` 替换。

### 2. 布尔化简
- **数据流**：`x AND TRUE` → `x`；恒真条件消除。
- **功能函数位置**：`sql/optimizer/conjunction_simplification_rule.cpp::ConjunctionSimplificationRule::rewrite`；`sql/optimizer/predicate_rewrite.cpp::PredicateRewriteRule::rewrite`。
- **实现原理**：合取中常量真值可短路化简；恒真 Filter 节点直接接管其子节点。

### 3. Projection Pruning
- **数据流**：收集整棵子树引用的列 → 写入 `TableGet` 的 `used_fields` → 物理扫描只输出这些列。
- **功能函数位置**：`sql/optimizer/projection_pruning_rule.cpp::ProjectionPruningRule::rewrite`；`sql/operator/table_get_logical_operator.h::set_used_fields`；`sql/operator/table_scan_physical_operator.cpp::set_used_fields`。
- **实现原理**：按表定义顺序保留被引用列，减少读取；`RowTuple::cell_at` 按字段原始下标访问空值位图，保证 `NULL` 正确。

### 4. Predicate Pushdown
- **数据流**：`Predicate` 上的简单比较条件下沉到 `TableGet` 的 `predicates`（`OR` 保守不下推）。
- **功能函数位置**：`sql/optimizer/predicate_pushdown_rewriter.cpp::PredicatePushdownRewriter::rewrite` / `get_exprs_can_pushdown`。
- **实现原理**：把“单表可判定”的比较条件下推到扫描层提前过滤；无法安全下推的表达式保留在 `Predicate`。

### 5. 冗余节点消除
- **数据流**：恒真 Filter 被移除；空谓词用常量真替代。
- **功能函数位置**：`sql/optimizer/predicate_rewrite.cpp::PredicateRewriteRule::rewrite`；`sql/optimizer/predicate_pushdown_rewriter.cpp::is_empty_predicate`。
- **实现原理**：判断谓词是否恒真/恒假，真则“删除该节点并接管子节点”，假则清空子节点。

## 测试要求

### 1. 能从任意 SELECT AST 解释每个 Plan 节点为何产生及数据流关系
- **数据流**：`SELECT name FROM student WHERE age>18` → `FROM`→`TableGet`、`WHERE`→`Predicate`、`SELECT`→`Project`，执行自底向上拉取。
- **功能函数位置**：`sql/optimizer/logical_plan_generator.cpp`；`sql/optimizer/physical_plan_generator.cpp`；`sql/executor/execute_stage.cpp`；`sql/operator/{table_scan,predicate,project}_physical_operator.cpp`。
- **实现原理**：子句与节点一一对应，执行遵循火山模型的 `open/next/close` 拉取模型；可用 `EXPLAIN` 展示计划树。

### 2. 优化前后结构变化
- **数据流**：`WHERE 1=1 AND age>10+8` → 常量折叠/布尔化简/谓词下推 → 等价于 `age>18` 的扫描过滤。
- **功能函数位置**：`sql/optimizer/arithmetic_simplification_rule.cpp`、`conjunction_simplification_rule.cpp`、`predicate_pushdown_rewriter.cpp`、`rewriter.cpp`。
- **实现原理**：`Rewriter` 反复应用规则直到不再变化；`EXPLAIN` 前后对比可见结构变化。

### UPDATE

- **功能函数位置**：`sql/stmt/update_stmt.cpp`、`sql/operator/update_physical_operator.cpp`。

- **功能函数位置**：`sql/operator/sort_physical_operator.cpp`。
- **实现原理**：按排序键表达式求值比较，支持升/降序。

- **数据流**：`GroupByLogicalOperator` → 哈希分组/标量聚合算子。

- **数据流**：`JoinLogicalOperator` → 嵌套循环/哈希连接。
- **功能函数位置**：`sql/operator/nested_loop_join_physical_operator.cpp`、`hash_join_physical_operator.cpp`。

## 2. 编译器扩展
### 错误恢复
- **数据流**：任一语句解析失败即被记录，`ParseStage` 检查全部节点后透出错误，进程不崩溃。
- **功能函数位置**：`sql/parser/yacc_sql.y`；`sql/parser/parse_stage.cpp`。
- **实现原理**：收集错误节点而非吞掉；非法输入统一转为结构化错误。
### 更复杂 AST
- **数据流**：`parse_defs.h` 节点可表达 JOIN、WHERE 布尔式、GROUP/ORDER、聚合等。
- **功能函数位置**：`sql/parser/parse_defs.h`。
- **实现原理**：AST 节点按语句/表达式分族，支持嵌套表达式树。
### 优化规则框架
- **数据流**：`Rewriter` 聚合多条 `RewriteRule`，反复迭代至收敛。
- **功能函数位置**：`sql/optimizer/rewriter.{h,cpp}`、`rewrite_rule.h`。
- **实现原理**：规则实现统一 `rewrite(oper, change_made)` 接口，可插拔。
### Plan 可视化
- **数据流**：`EXPLAIN` → `ExplainPhysicalOperator` 打印物理计划树。
- **功能函数位置**：`sql/operator/explain_physical_operator.cpp`；`sql/optimizer/optimizer_utils.cpp::dump_physical_plan`。
- **实现原理**：递归遍历算子链生成树状文本。
### 序列化
- **数据流**：元数据对象 → `serialize/deserialize` 读写文件。
- **功能函数位置**：`storage/table/table_meta.cpp`、`storage/index/index_meta.cpp`、`common/lang/serializable.h`。
- **实现原理**：统一可序列化接口，落盘与恢复。
### JSON 输出
- **数据流**：`QueryResult` → `to_json` → 通信层。
- **功能函数位置**：`net/native_communicator.cpp::to_json`；`service/query_result.h`。
- **实现原理**：值类型结果对象序列化为 JSON。

## 3. 系统扩展
### JOIN 执行算子
- **数据流**：连接逻辑算子 → 嵌套循环/哈希连接物理算子。
- **功能函数位置**：`sql/operator/nested_loop_join_physical_operator.cpp`、`hash_join_physical_operator.cpp`。

### EXPLAIN

- **功能函数位置**：`sql/operator/explain_physical_operator.cpp`。
- **实现原理**：输出物理执行计划树。
### Catalog 持久化

## 关注指标
### Crash
- **数据流**：异常输入/执行 → 连接断开或进程崩溃被捕获为 `CRASH`。
- **功能函数位置**：`SQL_description/test/run_tests.py::is_crash`。
- **实现原理**：识别断连/崩溃，单列为失败。
### Wrong Accept
- **数据流**：应报错却成功 → `WRONG_ACCEPT`。
- **功能函数位置**：`SQL_description/test/run_tests.py::evaluate_check`。
- **实现原理**：期望错误但执行成功即判错。
### Wrong Reject
- **数据流**：应成功却报错 → `WRONG_REJECT`。
- **功能函数位置**：`SQL_description/test/run_tests.py::evaluate_check`。
- **实现原理**：期望结果但返回错误即判错。
### Error Location
- **数据流**：错误位置与期望不符 → `WRONG_LOCATION`。
- **功能函数位置**：`SQL_description/test/run_tests.py::parse_location`。
- **实现原理**：解析消息中的行/列并与期望比对。
