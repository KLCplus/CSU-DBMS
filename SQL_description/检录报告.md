## 六、本轮修复的编译器相关缺陷

1. **词法器缺少 `OR`**：`or` 被当作 `ID`，导致 `a=1 or b=1` 结果错误、`(a=1 or b=1)` 语法错误 → 补 `OR` 关键字（`parser/lex_sql.l`）。
2. **NOT 优先级写反**：`not a=1 and b=1` 被解析为 `not (a=1 and b=1)` → 重排 `%left/%precedence`（`parser/yacc_sql.y`）。
3. **标识符大小写敏感**：`SELECT A FROM P` 报字段/表不存在 → 表名/列名查找改 `strcasecmp`（`storage/db/db.cpp`、`storage/table/table_meta.cpp`）。
4. **多余右括号被接受**：`where a=1);` 执行成功 → `ParseStage` 检查全部解析节点，任一条报错即反馈（`parser/parse_stage.cpp`）。
5. **字符串/转义**：支持 `''`/`""`/`\x`（`parser/lex_sql.l` + `parser/yacc_sql.y::unescape_quoted_string`）。
6. **语法 `expected:` 集合**：`%define parse.error custom` + `yyreport_syntax_error` 输出位置 + 实际符号 + 期望集合。
