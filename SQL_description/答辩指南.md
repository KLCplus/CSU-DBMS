# CSUDB 2026 答辩指南（个人部分）

> 本文只覆盖**本人负责的 5 项功能**：① 编译器 ② 代码自动补全 ③ 公网网页服务 ④ 公网 SDK 与 JDBC ⑤ 公网客户端。
> 队友负责的 `stmt/expr/operator/optimizer/executor/storage` 等**不在本文范围**，答辩时不要展开。

## 0. 五分钟总览

| # | 功能 | 一句话定位 | 核心代码入口 |
| --- | --- | --- | --- |
| 1 | 编译器 | 把 SQL 文本变成合法 AST + 语义校验，并复用同一套 Parser 支撑补全 | `src/observer/sql/parser/` |
| 2 | 代码自动补全 | 「Parser 期望符号 + 真实 Catalog」的确定性补全，叠加可选 Qwen2.5-Coder 小模型 | `src/observer/sql/autocomplete/` |

## 1. 编译器（SQL Parser / Compiler 层）

### 去哪看

| 功能点 | 文件 | 说明 |
| --- | --- | --- |
| 词法（token 定义） | `src/observer/sql/parser/lex_sql.l` | Flex 源文件；关键字、ID、数字、字符串、`NULL`、比较符等 |
| 语法（文法/语义动作） | `src/observer/sql/parser/yacc_sql.y` | Bison 源文件；产生式与 `%define parse.error custom` |
| AST / 解析结果结构 | `src/observer/sql/parser/parse_defs.h` | `ParsedSqlNode`、`SCF_*` 标志、`error` 结构 |
| 解析入口 | `src/observer/sql/parser/parse.cpp`、`parse.h` | `parse()` 驱动 `yyparse`，产出多条语句 |
| 解析阶段 | `src/observer/sql/parser/parse_stage.cpp` | 空节点/多语句/错误语句处理 |
| 语义（Resolve）阶段 | `src/observer/sql/parser/resolve_stage.cpp` | 调 `Stmt::create_stmt`，透出语义错误 |
| 表达式绑定与语义校验 | `src/observer/sql/parser/expression_binder.cpp`、`.h` | 字段/值/比较/连接/算术/聚集/cast 绑定；线程本地错误通道 |
| 补全用期望符号 | `src/observer/sql/parser/expected_tokens.h` | `collect_expected_tokens` 声明 |
| 生成物（不提交/不算） | `lex_sql.cpp`、`yacc_sql.cpp/.hpp` | 构建时生成，`.gitignore` 已忽略 |

配套文档：`SQL_description/spec.md`、`SQL_description/文件结构规划.md`、`SQL_description/功能对应.md`、`SQL_description/检录报告.md`。

### 原理（答辩讲解顺序）

1. **两段式编译管线**
   `SQL 文本 → (Flex) token → (Bison LALR) ParsedSqlNode(AST) → ParseStage → ResolveStage(Stmt + 语义检查) → 执行引擎`。
   编译器只负责「文本 → 合法 AST → Stmt」和语义校验，执行属于队友。

2. **词法与语法**
   `lex_sql.l` 定义 token，`yacc_sql.y` 用 LALR 文法把 token 归约为 `ParsedSqlNode`（`parse_defs.h`）；语义动作在归约时填充结构体。

3. **解析阶段（`parse_stage.cpp`）**
   - 空节点 → 返回 `RC::INTERNAL`；
   - 多语句 → 告警但只处理第一条；
   - **任意一条语句 `SCF_ERROR` 就返回 `RC::SQL_SYNTAX` 并透出 `error_msg`**，避免「尾部非法内容被静默忽略」。

4. **语义阶段与错误定位（`resolve_stage.cpp` + `expression_binder.*`）**
   - `Stmt::create_stmt` 做表/列存在性、类型匹配等检查；
   - 表达式绑定（`select *` 展开、字段绑定到真实 `Table/Field`、比较/算术/聚集类型检查）；
   - 语义错误在绑定阶段只有 `RC`，用**线程本地槽位** `set_binder_error_message / get_binder_error_message` 把带行列的结构化消息透到 `resolve_stage`，再回给用户；每次语句开始前 `reset_binder_error_message()`。

5. **为补全服务的复用（关键亮点）**
   `expected_tokens.h` + `yacc_sql.y` 里的 `collect_expected_tokens`：在 SQL 前缀末尾追加非法哨兵字符，让 Parser 在光标处报错，再用 `%define parse.error custom` 的 `yypcontext_expected_tokens` 取出**该位置合法的 terminal 集合**。这样补全与语法诊断**共用同一份语法**，不引入第二套 Parser。

6. **本人扩展的语法/语义**
   在文法与词法上补充了 `UPDATE`、显式 `JOIN`、`NULL`、`DATE`、`ORDER BY/GROUP BY` 等产生式及相关语义校验（**注意：排序、连接、更新算子的执行实现属于执行/存储方向，不是本文范围**）。

### 边界（不要说）

`src/observer/sql/stmt/`、`expr/`、`operator/`、`optimizer/`、`executor/`、`src/observer/storage/` 都不是本人实现。

| 设计文档 | `SQL_description/CSU_DBMS_SQL_Autocomplete_Implementation_Plan.md` |

### 原理

**混合架构：确定性补全 + 可选小模型。** 三条铁律：
1. **不让 LLM 决定 SQL 合法性**——语法/表/列由 Lexer/Parser/Catalog 保证；
2. **不引入第二套 Parser**——关键字来自 bison 期望符号集合；
3. **模型是增强项**——不可用/超时/校验失败时照常确定性补全，不阻塞不报错。

- **确定性链**：`current_statement_extractor` 取光标所在语句 → `sql_text_scanner` 扫描上下文 → `grammar_completion_provider` 用 `collect_expected_tokens` 给关键字（并用同一 Parser 试探确认续写）→ `catalog_completion_provider` 给真实表/列 → `completion_scope` 处理 `FROM/JOIN/INSERT INTO` 的 scope → `sql_capabilities` 门禁（只推项目真实支持方言，如 `INT/CHAR/FLOAT/VECTOR/DATE`，`HAVING/LIMIT/ALTER` 等一律不推）→ `completion_engine.complete()` 汇总。
- **模型链**：`model_provider` 先健康检查 → `model_context_builder` 拼「方言 + 相关 schema」上下文 → `llama_completion_client` 发 `/infill`（带 deadline）→ `model_completion_validator` 用方言/Parser/Catalog 三重校验并裁到**最长合法前缀**，失败即丢弃。
- **协议**：native 新增 `{"type":"complete","sql":...,"cursor":...,"max_items":12,"want_model":...}`；响应 `rows` 每行 `[insert_text, display_text, kind, source, replace_start, replace_end, score, detail]`，`attributes.ghost_text` 为模型 ghost，`attributes.model_used` 标识是否用模型。
- **模型**：`Qwen/Qwen2.5-Coder-1.5B`（Base）GGUF，P40 上 `-ngl 99 -c 4096 -np 1 -fa off`，仅监听 `127.0.0.1:8012`。

# 或交互内

# 单测 / 集成测试

## 3. 公网网页服务

### 去哪看

| 功能点 | 文件 / 位置 |
| --- | --- |
| Web 网关（HTTP + 会话） | `src/obclient/web/csudb_web.py` |
| 前端页面/脚本/样式 | `src/obclient/web/index.html`、`app.js`、`app.css` |
| 协议嗅探代理（公网 8157） | `scripts/tcp_proxy.py` |
| 隧道 | `cloudflared tunnel --url http://127.0.0.1:8765`（部署时启动） |
| 静态站（GitHub Pages） | `gh-pages` 分支：`index.html`、`app.js`、`app.css`、`config.js` |
| 启动脚本 | `src/obclient/web_console_launcher.{h,cpp}`、`/web` 命令 |

### 原理

- **网关 `csudb_web.py`**：`ThreadingHTTPServer`，`SessionStore` 把随机 token 映射到 `csudb.Connection`；接口：`/`、`/app.css`、`/app.js`、`/api/health`、`/api/status`、`/api/pages`、`/api/databases`、`/api/tables`、`/api/table`、`/api/schema`，以及 `POST /api/connect`、`/api/logout`、`/api/query`、`/api/use`、`/api/complete`。默认强制只监听 loopback。
- **公网暴露 = 协议嗅探代理 + 隧道**：
  - `tcp_proxy.py` 监听 `0.0.0.0:8157`，用 `recv(8, MSG_PEEK)` **只看不消费**前 8 字节判断协议：若以 `GET/POST/HEAD/...` 开头 → HTTP 转 `127.0.0.1:8765`，否则 → native 转 `127.0.0.1:6789`。于是**一个端口同时给网页和 SDK/CLI 用**。
  - `cloudflared` 快速隧道把 `127.0.0.1:8765` 映射成一个 `*.trycloudflare.com` 公网 HTTPS 地址。
- **跨域与前端直连**：`csudb_web.py` 增加 CORS（`Access-Control-Allow-Origin` 回显 Origin、允许 `X-CSUDB-Session` 头、处理 `OPTIONS`）与 `X-CSUDB-Session` 请求头回退，便于 GitHub Pages 上的静态前端跨域调用；前端 `app.js` 用 `window.CSUDB_API_BASE`（`gh-pages/config.js` 配置隧道地址）拼接请求，并用 `location.host` 显示当前访问地址。
- **本人对 Web 的改动**：登录/会话修复（跳转与 token 失效）、SQL 补全下拉与 ghost 面板、CORS、`API_BASE`、地址显示、公网发布。**基础版式与初始 Console 由队友提交，不要当成自己的内容讲。**

### 原理

- **Python（DB-API 2.0 风格，仅标准库）**：`_NativeConnection` 用「UTF-8 JSON + `\0` 结尾」做 native 报文；`connect()` 登录建会话；`_bind` 把 `%s` 占位符按 SQL 字面量规则转义（`None→NULL`、bool→1/0、数字原样、其余加引号转义）；`Cursor` 物化结果并支持 `fetchone/many/all`、迭代、`description`、`rowcount`；`server_info`/`buffer_snapshot` 为诊断扩展。异常层级对齐 DB-API。
- **JDBC 4（零第三方依赖）**：`CsuDbDriver` 通过 `META-INF/services` + 静态块自动注册；URL `jdbc:csudb://HOST:PORT/DATABASE`，属性 `user/password/connectTimeout`；`JdbcProxies` 用 `java.lang.reflect.Proxy` 实现 `Connection/Statement/PreparedStatement/ResultSet/ResultSetMetaData/DatabaseMetaData`，**未实现的方法统一抛 `SQLFeatureNotSupportedException`**；`?` 参数在驱动端做字面量转义（非服务端 PreparedStatement）；列类型名映射到 JDBC 类型；服务端错误码映射为 `SQLException.getErrorCode()`。
- **公网复用**：SDK/JDBC 都走 native 协议，直接连 `117.50.163.43:8157`，与网页共用同一嗅探端口。

## 7. 可能被问的问题（备答）

1. **为什么补全不直接用大模型生成 SQL？**
   因为合法性必须由现有 Lexer/Parser/Catalog 保证；模型只做「续写增强」，且经过方言/Parser/Catalog 三重校验与最长合法前缀裁剪，超时或失败自动降级为确定性补全。

2. **补全的关键字从哪来？会不会和维护两套语法？**
   来自同一份 bison 语法：给前缀加哨兵字符触发错误，用 `yypcontext_expected_tokens` 取期望 terminal 集合。只有一套 Parser。

3. **语义错误怎么定位到行列？**
   绑定阶段只有 `RC`，用线程本地错误槽位把带行列的消息传出，`resolve_stage` 在语句开始时 `reset`、失败时读取并回给用户。

4. **一个公网端口怎么同时服务网页和 SDK？**
   8157 上的嗅探代理用 `MSG_PEEK` 看前几个字节：HTTP 方法开头转 8765，否则转 6789 原生协议。

5. **SDK/JDBC 的 `?`/`%s` 是服务端预编译吗？**
   不是，是驱动端按字面量规则转义；服务端 PreparedStatement 属于后续工作。返回值当前统一以字符串传输。

6. **客户端为什么能「解压即用」？**
   Release 构建 + `STATIC_STDLIB=ON`，只依赖系统 libc/libm；`--url` 可指向公网服务。
