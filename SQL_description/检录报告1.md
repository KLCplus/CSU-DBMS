# 检录报告 1：SQL 编译器需求对照检查

- 检查对象：`src/observer/sql/`（OceanBase Miniob 课程代码库）
- 对照文档：`doc/requirements.md`（SQL 编译器需求拆解）
- 检录日期：2026-09-09
- 结论概览：核心增删改查、AND、词法/语法/语义的基本链路已具备，但需求中的 **OR / NOT / 括号 / 注释 / 多语句 / 常量折叠 / ORDER BY / 显式 JOIN / UPDATE 执行 / INSERT 类型匹配 / 语义错误定位** 等项未完整满足。

## 一、必备能力（CREATE / INSERT / SELECT / DELETE / WHERE / 比较 / AND / OR / NOT / 括号）

| 需求 | 状态 | 说明与证据 |
| --- | --- | --- |
| CREATE | ✅ 满足 | 语法 `create_table_stmt`（`sql/parser/yacc_sql.y:324`），执行 `create_table_executor.cpp` 调用 `db->create_table()` 注册元数据并建表 |
| INSERT | ✅ 满足 | 语法 `insert_stmt`（`yacc_sql.y:412`），逻辑规划 `logical_plan_generator.cpp` → `InsertLogicalOperator`，物理执行 `insert_physical_operator.cpp` |
| SELECT | ✅ 满足 | 语法 `select_stmt`（`yacc_sql.y:485`），支持 `SELECT exprs FROM rel_list where group_by` |
| DELETE | ✅ 满足 | 语法 `delete_stmt`（`yacc_sql.y:461`），执行链路 `delete_logical_operator` → `delete_physical_operator.cpp` |
| WHERE | ✅ 满足 | `select_stmt` 构建 `FilterStmt`；逻辑规划生成 `PredicateLogicalOperator`（`logical_plan_generator.cpp:152`） |
| 比较运算 | ✅ 满足 | 支持 `= < > <= >= !=`、`<>`（词法 `lex_sql.l:134-140`，`ComparisonExpr` 计算 `expression.cpp`） |
| AND | ✅ 满足 | WHERE 条件以 `condition_list ... AND` 连接（`yacc_sql.y:632`），执行期合并为 `ConjunctionExpr(AND)` |
| OR | ❌ 未满足 | 词法、语法均无 OR：`lex_sql.l` 无 OR 关键字，`yacc_sql.y` 的 condition 只支持 AND 链。`ConjunctionExpr` 虽实现了 OR 求值逻辑，但 SQL 层无法生成 OR |
| NOT | ❌ 未满足 | 词法无 NOT 关键字，语法无一元 NOT 表达式 |
| 括号 | ⚠️ 部分 | SELECT/算术表达式中支持括号（`yacc_sql.y:548` `LBRACE expression RBRACE`）；但 WHERE 条件不支持括号分组（condition 文法无括号项） |

## 二、进阶版本（UPDATE / ORDER BY / GROUP BY / JOIN / 算术 / NULL）

| 需求 | 状态 | 说明与证据 |
| --- | --- | --- |
| UPDATE | ⚠️ 仅解析 | 有语法 `update_stmt`（`yacc_sql.y:472`）但与 stmt：`logical_plan_generator.cpp` 无 UPDATE 分支（`create()` 只处理 CALC/SELECT/INSERT/DELETE/EXPLAIN，其余走 `RC::UNIMPLEMENTED`），无任何 update 物理算子文件 → 不能执行 |
| ORDER BY | ❌ 未满足 | 词法、语法均无 ORDER BY 关键字；优化器/算子目录无排序（sort）算子 |
| GROUP BY | ✅ 满足 | 语法 `GROUP BY expression_list`（`yacc_sql.y:704`），逻辑规划 `create_group_by_plan`，物理算子 `ScalarGroupByPhysicalOperator`/`HashGroupByPhysicalOperator` |
| JOIN | ⚠️ 隐式 | 无显式 JOIN 关键字；`FROM rel_list` 多表生成 `JoinLogicalOperator` → `NestedLoopJoinPhysicalOperator`（`physical_plan_generator.cpp:313`）。`hash_join` 仅为空壳文件。只能做笛卡尔积式多表连接，无 JOIN 条件语法 |
| 算术表达式 | ✅ 满足 | `expression: e+e \| e-e \| e*e \| e/e \| -e`（`yacc_sql.y:535`），`ArithmeticExpr::calc_value` 执行 |
| NULL | ⚠️ 代码侧部分 | 需求未找到 `IS NULL/NOT NULL` SQL 支持；值/类型系统侧有 NULL 相关处理，但无对应 SQL 文法入口 |

## 三、词法分析器

| 需求 | 状态 | 说明与证据 |
| --- | --- | --- |
| 输入：SQL 文件 / 单条 / 多条 | ❌ 单条 | `commands: command_wrapper opt_semicolon`（`yacc_sql.y:213`，注释明确"should be a list but I use a single command instead"）；`parse_stage.cpp:45` 对多语句仅告警、只处理第一条 |
| 输出 `<TokenType,Lexeme,Line,Column>` | ⚠️ 部分 | flex 通过 `YY_USER_ACTION` 记录 `yylloc`（`lex_sql.l:16`），供 yacc 定位；但 lexer 不对外输出含位置的行列 token 流，位置仅在语法/结果中体现 |
| 识别关键字 | ✅ | `lex_sql.l:86-128` |
| 识别标识符 | ✅ | `{ID} ... RETURN_TOKEN(ID)`（`lex_sql.l:129`） |
| 识别常量 | ✅ | 整数 `{DIGIT}`、浮点 `{DIGIT}.{DIGIT}`（`lex_sql.l:81-82`） |
| 识别运算符 | ⚠️ 部分 | 支持 `= <= <> != < >= >`；**缺失 `==`**（需求列出但要 `==` 会被拆成两个 `=` 而报语法错） |
| 识别分隔符 | ✅ | `;` `( )` `,` `.` 等 |
| 跳过空白 | ✅ | `{WHITE_SPACE}` / `\n`（`lex_sql.l:78-79`） |
| 跳过注释 | ❌ 未满足 | 无任何注释规则，`-- ...` 会被当作两个 `-` 运算符、`/* */` 无匹配 → 需求提供的注释型输入用例无法通过 |
| 处理字符串 | ⚠️ 部分 | 支持 `'...'` 与 `"..."`（`lex_sql.l:146-147`）；字符串中的内容不允许任何引号 |
| 处理转义 | ❌ 未满足 | 正则 `'[^']*\'` 无转义机制；`'Tom''s book'`（需求用例）会被拆成 `'Tom'` 与 `'s book'` 两段，语义与标准 SQL 不一致 |
| 大小写不敏感 | ✅ | `%option case-insensitive`（`lex_sql.l:60`） |
| 非法输入不崩溃+报错 | ⚠️ 部分 | 非法字符走 `.` → `return yytext[0]`（`lex_sql.l:149`）进而产生语法错误，**不崩溃**、能带行列号；但未区分"非法字符/未闭合字符串/非法数字"的原因类型 |
| 整段用例（WHERE age>=18 AND name!='Tom'） | ⚠️ 部分 | 该语句可正常解析执行；但期望逐 token 输出的 `<Type,Lexeme,(行列)>` 结构化结果未以该形式对外呈现 |

## 四、语法分析

| 需求 | 状态 | 说明与证据 |
| --- | --- | --- |
| 输入 Token 流 → 输出 AST | ✅ | yacc 构建 `ParsedSqlNode` 等 AST（`parse_defs.h`、`yacc_sql.y`） |
| 优先级 NOT>比较>AND>OR | ❌ 未满足 | NOT 与 OR 未实现，布尔逻辑只在 `condition_list` 中平铺 AND；比较与算术表达式彼此分离，不构成需求中的单一优先级链 |
| 括号改变结合结构 | ⚠️ 部分 | 算术表达式可用括号；WHERE 条件不可 |
| 消除左递归 | ✅（由 bison 处理） | 文法本身即 LR，列表类规则用右递归/左递归由 bison 消解，无手写递归下降问题 |
| 构造 FIRST/FOLLOW 集 | ✅（由 bison 生成） | yacc 自动生成分析表，等价满足；但非手写演示 |
| LL(1) 表 | ❌ 未使用 | 采用 bison(LALR) 而非 LL(1)/递归下降，未显式构造 LL(1) 表 |
| 递归下降 | ❌ 未使用 | 由 bison 自底向上代替 |
| LR（可选挑战） | ✅（由 bison 提供） | bison 即自底向上 LR 分析器 |
| 语法诊断（位置+实际+期望集合） | ⚠️ 部分 | `yyerror` 生成 `SCF_ERROR`，记录 `line/column/error_msg`（`yacc_sql.y:22`），并 `%define parse.error verbose`；**但未提供 `expected: ...` 期望符号集合** |
| 语法错误不崩溃 | ✅ | 统一转换为 `SCF_ERROR` 节点，`parse_stage.cpp:50` 返回 `RC::SQL_SYNTAX` |

## 五、语义分析

| 需求 | 状态 | 说明与证据 |
| --- | --- | --- |
| 验证表存在性 | ✅ | `SelectStmt::create` 经 `db->find_table()`，缺失返回 `SCHEMA_TABLE_NOT_EXIST`（`select_stmt.cpp:53`）；`ExpressionBinder::bind_unbound_field_expression` 也校验（`expression_binder.cpp:133`） |
| 验证列存在性 | ✅ | field 查不到返回 `SCHEMA_FIELD_MISSING`（`expression_binder.cpp:164-168`） |
| 名字绑定 | ✅ | `ExpressionBinder` 把 `UnboundFieldExpr` 解析为 `FieldExpr`（`expression_binder.cpp:133`） |
| 类型一致性 | ⚠️ 部分 | 比较两侧类型不同时按 `cast_cost` 自动插入 `CastExpr`（`logical_plan_generator.cpp:169-206`）；但**无法转换成合法类型时仅返回 `UNSUPPORTED`，不构造成带位置的语义错误**；算术 `age+'abc'` 会按 `value_type()` 直接归为 FLOATS 而不是报"cannot apply + to INT and VARCHAR" |
| INSERT 匹配 | ⚠️ 部分 | 只校验**值的个数**与表字段数一致（`insert_stmt.cpp:45-48`，不匹配返回 `SCHEMA_FIELD_MISSING`）；**不做逐列类型匹配**，不产出需求中的 `TypeMismatch: id expects INT...` 报告 |
| Catalog 提供 createTable/findTable/findColumn/getType | ⚠️ 部分 | 具备 `db->create_table`（建表注册元数据）、`db->find_table`、`TableMeta::field()`、类型经 `DataType::type_instance()`；接口**以 Table/TableMeta/DataType 形态存在**，非需求命名的独立 `getType` 接口 |
| Catalog 服务执行引擎与持久化 | ✅ | 元数据由 `table_meta`/`catalog` 管理并落盘（`storage/`） |
| 简化类型系统（集中管理） | ⚠️ 部分 | `AttrType+DataType`（`common/type/`）集中了 `cast_cost` 等类型能力；但算术/比较规则仍散落在 `expression.cpp`、`logical_plan_generator.cpp` 中，未完全集中在单一类型规则层 |
| 语义错误报告（类型+位置+原因） | ❌ 未满足 | 语义错误仅返回 RC 返回码（如 `SCHEMA_TABLE_NOT_EXIST`），**不带行列位置**，无 `SemanticError at line,column` 结构 |

## 八、关键堵点汇总（建议优先补齐）

1. **词法器**：注释（`--`、`/* */`）、字符串转义/连续引号、`==` 运算符均缺失。
2. **布尔表达式**：WHERE 的 OR、NOT、括号、以及条件中的算术表达式均不受支持 → 直接影响"优先级 NOT>比较>AND>OR"与"常量折叠"两项验收。
3. **多语句**：解析器只处理第一条 SQL。
4. **语义错误定位**：语义错误仅返回返回码，无行列位置与结构化 `SemanticError`。
5. **INSERT 类型匹配**：只校验个数，未逐列做类型校验与 `TypeMismatch` 报告。
6. **UPDATE 不可执行**、**ORDER BY 缺失**、**显式 JOIN 缺失**。
